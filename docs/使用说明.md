## 1. 启动与停止

### 1.1 环境检查

| 依赖 | 要求 | 检查命令 |
| --- | --- | --- |
| JDK | 17 及以上 | `java -version` |
| Maven | 3.8 及以上 | `mvn -v` |
| MySQL | 8.0 及以上，已启动 | `mysql --version` |
| Node.js | 18 及以上 | `node -v` |

数据库需要提前创建，账号密码与后端配置一致。首次使用请按 README 的「快速开始」执行建库和授权 SQL。

### 1.2 一键启动（Windows）

双击根目录的 `start-local.bat`。

脚本会按顺序检查：

1. 3306 端口是否存在 MySQL，不存在则直接退出并提示；
2. 8080 是否已有后端，未运行则优先用 `mvn spring-boot:run` 启动，没有 Maven 时回退到已打包的 jar；
3. 等待后端接口可访问，再检查 5173；
4. 5173 未运行则执行 `npm run dev`，首次缺少 `node_modules` 会先安装依赖；
5. 默认打开浏览器首页。

已经在运行的服务会显示 `[skip]`，不会重复启动。只想启动服务、不打开浏览器时：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1 -NoBrowser
```

### 1.3 手动启动

后端：

```bash
cd homestay-booking
mvn spring-boot:run
```

前端：

```bash
cd homestay-web
npm install
npm run dev
```

### 1.4 确认启动成功

| 检查项 | 地址或命令 | 预期 |
| --- | --- | --- |
| 后端接口 | <http://localhost:8080/api/public/room-types> | 返回 `code: 0` 的 JSON |
| 接口文档 | <http://localhost:8080/swagger-ui.html> | 打开 Swagger 页面 |
| 前端首页 | <http://localhost:5173/> | 显示房型列表 |
| 管理端 | <http://localhost:5173/admin> | 未登录时跳转登录页 |

### 1.5 停止服务

关闭由脚本弹出的后端、前端 PowerShell 窗口即可停止对应服务。

如果窗口已经丢失，可以先查端口再结束进程（请确认进程确实是本项目的 Java / Node）：

```powershell
Get-NetTCPConnection -LocalPort 8080,5173 -State Listen |
  Select-Object LocalPort, OwningProcess
```

拿到 `OwningProcess` 后，用任务管理器结束，或执行 `Stop-Process -Id <PID>`。

## 2. 账号、演示数据与初始化

### 2.1 房东账号

首次启动时，如果 `users` 表中没有任何 `HOST` 角色账号，后端会自动创建：

| 账号 | 密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `admin123` | `HOST` | 可进入 `/admin` 管理端 |

该账号只用于本地调试。生产环境必须更换密码。

当前版本没有修改密码的页面或接口。需要更换时，有两种方式：

1. 先补充一个修改密码接口，再用接口更新；
2. 在数据库中把 `users.password` 替换为新的 BCrypt 密文。

BCrypt 密文不能手工拼写，必须由程序生成。可以在项目的测试或临时类中执行：

```java
System.out.println(new BCryptPasswordEncoder().encode("你的新密码"));
```

把输出结果写入 `users.password` 即可。不要使用 MD5 或明文替换。

### 2.2 房客账号

房客通过前端「注册」页面自行创建，注册接口固定写入 `CUSTOMER` 角色，不能注册成房东。

如果登录提示“用户名或密码错误”，先确认是否注册成功：

```sql
SELECT id, username, role, status FROM users ORDER BY id;
```

`status = 0` 表示账号被禁用，需要在数据库中改回 `1`。

### 2.3 写入演示数据

演示数据默认关闭，避免误写生产库。开启方式二选一：

方式一，启动时临时传入参数：

```bash
cd homestay-booking
mvn spring-boot:run -Dspring-boot.run.arguments=--app.seed.enabled=true
```

方式二，把 `application.yml` 中的 `app.seed.enabled` 改为 `true`，重启后改回 `false`。

写入条件与内容：

- 只有 `room_type` 表为空时才执行，已有房型会直接跳过；
- 写入 2 个房型：山景大床房、庭院家庭房；
- 写入 4 个房间：201、202、301、302；
- 写入未来 90 天的日历，初始库存等于该房型可用房间数。

演示数据不包含房客账号和订单，需要自行注册、下单。

### 2.4 清空并重建数据库（危险）

仅用于本地测试。该操作会删除全部账号、房型、房间、日历和订单，且不可恢复。

```sql
DROP TABLE IF EXISTS order_log;
DROP TABLE IF EXISTS order_stay;
DROP TABLE IF EXISTS order_room;
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS room_calendar;
DROP TABLE IF EXISTS room;
DROP TABLE IF EXISTS room_type;
DROP TABLE IF EXISTS users;
```

重启后端会自动重新建表，并再次创建 `admin / admin123`。如需演示房型，再按 2.3 开启 seed。

## 3. 房客端操作

### 3.1 浏览房源

打开 <http://localhost:5173/>，首页展示所有已上架房型。每张卡片包含封面、名称、床型、面积、可住人数和价格。

- 列表分页加载；
- 关键词可按房型名称筛选；
- 房型被房东下架后，首页和搜索都不再显示。

### 3.2 搜索房源

在首页选择入住日期、离店日期、人数和间数，点击搜索进入结果页。

搜索会同时检查两件事：

1. 区间内每一晚的日历是否开放且库存足够；
2. 是否存在足够数量的、整段日期都空闲的物理房间。

只有两者同时满足才会出现在结果中。选择 11-20 至 11-22，表示住 11-20、11-21 两晚，11-22 当天离店，不占用 11-22 的库存。

人数规则是「单间可住人数 × 间数 ≥ 总人数」。例如两间可住 2 人的房，最多可填 4 人。

### 3.3 查看详情与报价

点击房型卡片进入详情页：

- 页面展示未来 30 天的价格与可订状态；
- 选择日期和间数后，右侧会自动计算总价；
- 总价 = 每晚价格累加 × 间数；
- 不可订时会显示具体原因，例如“未开放预订”“已关房”“仅剩 1 间”“没有同一间房可连续入住”。

报价只做展示和预校验，最终能否下单以提交时的库存为准。

### 3.4 注册与登录

点击右上角登录，没有账号时先注册。

| 字段 | 要求 |
| --- | --- |
| 用户名 | 4 到 20 位，字母、数字或下划线 |
| 密码 | 6 到 32 位 |
| 昵称 | 必填 |
| 手机号 | 选填，填写时需符合手机号格式 |

登录成功后 Token 保存在浏览器 localStorage，刷新页面不会退出。退出登录会同时清除本地会话。

### 3.5 提交订单

在详情页选择日期、间数，点击预订：

1. 未登录会先跳转登录，登录后可返回；
2. 填写联系人、联系电话和备注；
3. 提交后系统扣减每晚库存、分配具体房间，并生成订单；
4. 成功后会跳转「我的订单」，状态为「待确认」。

下单失败时页面会保留已填信息，常见原因是库存刚被其他订单占用，或没有连续空房，按提示更换日期或减少间数即可。

### 3.6 我的订单

「我的订单」按状态分为：全部、待确认、已确认、已入住、已完成、已取消。

- 点击订单可查看详情、分配房号和状态时间线；
- 待确认、已确认的订单可以取消；
- 已入住、已完成、已取消的订单不能取消；
- 取消后库存立即恢复，状态变为「已取消」。

取消前会弹出确认框。取消是不可撤销操作，如需再次入住请重新下单。

## 4. 管理端操作

### 4.1 进入管理端

访问 <http://localhost:5173/admin>，使用房东账号登录。

- 房客账号会被拒绝，并提示“仅房东账号可进入管理台”；
- Token 过期后会跳转登录页，重新登录即可；
- 管理端共有四个菜单：房型管理、房间管理、日历库存、订单管理。

### 4.2 房型管理

| 操作 | 说明 |
| --- | --- |
| 新增 | 填写名称、基准价、最多入住人数、床型、面积、封面图、描述 |
| 修改 | 名称不能与其他房型重复；只改价格时不会误报重名 |
| 上架 / 下架 | 下架后房客端列表、搜索、详情都不再展示 |
| 删除 | 房型下仍有房间时会拒绝，需先删除房间 |

封面图建议使用本地路径，例如 `/images/room-mountain.jpg`。使用外部链接时，首次加载可能较慢或失效。

基准价只是日历未配置时的兜底价格。实际售价以日历中的每日价格为准。

### 4.3 房间管理

| 字段 | 说明 |
| --- | --- |
| 所属房型 | 必选，决定该房间计入哪个房型的库存 |
| 房间号 | 全局唯一，例如 201 |
| 楼层 | 选填 |
| 状态 | 可用 / 维修 |

房间状态会影响三处逻辑：

- 生成日历时，库存只统计「可用」房间；
- 房客搜索时，只统计「可用」房间；
- 下单分配时，只从「可用」房间中选择。

把房间改为维修不会影响已有订单，但该房间不再参与新的分配。新增房间或恢复可用后，已经生成过的日期不会自动增加库存，需要用日历页的「区间批量设置」手工调整；「生成日历」只会为尚无记录的日期补库存，不会覆盖已有日期的库存。

### 4.4 日历库存

这是管理端最重要的页面，分为三种操作。

#### 生成日历

1. 在顶部选择房型；
2. 点击「生成日历」；
3. 选择起止日期，默认今天到 29 天后；
4. 确认后，系统按该房型可用房间数写入每晚库存，价格为房型基准价。

已存在的日期会自动跳过，不会覆盖手工改过的价格和库存。开始日期不能早于今天，单次最多 366 天。

#### 区间批量设置

用于节假日调价、整体关房等场景：

- 选择起止日期；
- 只填写需要修改的项：价格、库存、状态；
- 留空的项保持不变；
- 状态 `1` 为开放，`0` 为关房。

价格和库存允许填 `0`，库存 `0` 表示售罄。

#### 单日修改

点击日历中的某一天，可单独修改该晚的价格、库存或开放状态。

如果该天没有日历记录，页面会提示先生成日历。未生成的日期在房客端视为不可订。

#### 月度统计

页头会统计当前月份：

- 已生成天数：有多少天存在日历记录；
- 关房天数：状态为关闭的天数；
- 售罄天数：库存为 0 的天数。

如果已生成天数明显少于当月天数，说明这个月还没有配置完整。

### 4.5 订单管理

订单列表支持按状态和关键词筛选，点击订单可打开详情抽屉，查看联系人、分配房号、金额和状态时间线。

| 当前状态 | 可用操作 | 库存影响 |
| --- | --- | --- |
| 待确认 | 确认、拒绝 | 拒绝时归还库存 |
| 已确认 | 办理入住、拒绝 | 拒绝时归还库存 |
| 已入住 | 完成 | 不变 |
| 已完成 | 无 | 不变 |
| 已取消 | 无 | 已归还 |

操作规则：

- 确认后订单进入「已确认」，房客可按时入住；
- 拒绝等同于取消，必须归还库存，可填写原因；
- 办理入住后不能再取消；
- 完成是终态，不再改变库存；
- 每次操作都会写入状态日志，房客详情页可以看到。

## 5. 业务规则速查

### 5.1 日期与晚数

采用半开区间 `[入住日, 离店日)`。

| 入住 | 离店 | 晚数 | 占用的夜晚 |
| --- | --- | --- | --- |
| 11-20 | 11-21 | 1 | 11-20 |
| 11-20 | 11-22 | 2 | 11-20、11-21 |
| 11-20 | 11-20 | 0 | 非法，离店必须晚于入住 |

同一间房 11-21 离店、另一单 11-21 入住，不构成冲突。

### 5.2 库存如何变化

以山景房两间、11-20 和 11-21 各剩 3 间为例，预订两间两晚：

| 阶段 | 11-20 库存 | 11-21 库存 |
| --- | --- | --- |
| 下单前 | 3 | 3 |
| 下单后 | 1 | 1 |
| 取消后 | 3 | 3 |

取消时按订单实际占用的夜晚逐晚归还，每晚加回订单间数。

### 5.3 为什么每晚有余量仍可能订不上

假设只有 201 和 202 两间房：

- 11-20：201 空闲，202 已被占用；
- 11-21：201 已被占用，202 空闲。

两晚的剩余库存都是 1，但没有任何一间房能连续住两晚。系统会拒绝新订单并提示更换日期或减少间数，不会为了接单去改动已有订单的房间。

### 5.4 订单状态机

```text
PENDING ──确认──▶ CONFIRMED ──入住──▶ CHECKED_IN ──完成──▶ COMPLETED
   │                   │
   └────取消/拒绝───────┴──────▶ CANCELLED
```

已入住、已完成、已取消都不能回退到其他状态。

### 5.5 金额

- 所有金额使用 `DECIMAL(10,2)`，前端展示两位小数；
- 总价 = 单间每晚价格累加 × 间数；
- 当前版本不包含支付、退款、优惠券和税费。

## 6. 配置修改

### 6.1 开发配置

文件：`homestay-booking/src/main/resources/application.yml`

| 配置 | 说明 | 修改建议 |
| --- | --- | --- |
| `server.port` | 后端端口 | 修改后同步修改前端 Vite 代理 |
| `spring.datasource.*` | 数据库连接 | 与本地 MySQL 保持一致 |
| `app.jwt.secret` | JWT 签名密钥 | 至少 32 字节，生产必须替换 |
| `app.jwt.expire-minutes` | Token 有效期 | 默认 1440 分钟 |
| `app.seed.enabled` | 演示数据开关 | 写入完成后改回 `false` |
| `mybatis-plus...log-impl` | SQL 日志 | 生产环境关闭 |

### 6.2 前端代理

文件：`homestay-web/vite.config.js`

```js
server: {
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
    }
  }
}
```

修改后端端口后，这里的 `target` 也要同步修改。

### 6.3 生产配置

使用 `application-prod.yml`，通过环境变量注入敏感项：

```bash
export DB_URL='jdbc:mysql://127.0.0.1:3306/homestay?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true'
export DB_USERNAME='homestay_app'
export DB_PASSWORD='你的数据库密码'
export JWT_SECRET='至少32字节的随机字符串'
export SERVER_PORT=8080
export LOG_FILE='/var/log/homestay-booking.log'

java -jar homestay-booking-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

生产配置中 `app.seed.enabled` 固定为 `false`，不会写入演示数据。

## 7. 常见问题

### 7.1 启动脚本提示未检测到 MySQL

原因：3306 端口没有服务监听，或 MySQL 未启动。

处理：

```powershell
Get-Service | Where-Object { $_.Name -like '*mysql*' }
Start-Service MySQL80
```

服务名以本机安装结果为准。

### 7.2 后端报 Access denied for user

原因：数据库账号、密码或授权不匹配。

处理：用管理员账号重新执行授权，并核对 `application.yml`：

```sql
CREATE USER IF NOT EXISTS 'homestay_app'@'localhost' IDENTIFIED BY 'Homestay@2026';
GRANT ALL PRIVILEGES ON homestay.* TO 'homestay_app'@'localhost';
FLUSH PRIVILEGES;
```

### 7.3 登录成功但管理端 403

原因：当前账号不是 `HOST`。注册接口固定创建 `CUSTOMER`。

处理：使用 `admin` 登录；或把测试账号角色改为房东：

```sql
UPDATE users SET role = 'HOST' WHERE username = '你的账号';
```

修改后退出并重新登录，让前端重新获取用户信息。

### 7.4 刷新页面后变成未登录

原因：localStorage 中的 Token 或用户信息被清除、过期或损坏。

处理：重新登录。若频繁出现，检查浏览器是否启用了退出即清理数据的隐私模式。

### 7.5 搜索显示有房，下单却返回 409

可能原因：

1. 库存刚被其他订单占用；
2. 每晚有余量，但没有同一间房能连续入住；
3. 日历在你搜索之后被房东关闭或改价改库存。

处理：刷新报价后重试；仍失败时更换日期、减少间数，或在管理端检查对应日期的库存和状态。

### 7.6 日历页面没有数据

原因：该房型还没有生成日历，或选择的月份超出已生成范围。

处理：点击「生成日历」，选择包含目标月份的区间。未生成的日期房客端不可订。

### 7.7 图片不显示

原因：`room_type.cover_image` 指向了失效的远程地址，或文件名拼写错误。

处理：把图片放到 `homestay-web/public/images/`，数据库中的路径改为 `/images/文件名.jpg`。首页和登录页的大图也使用同一目录下的本地图片。

### 7.8 前端请求 404 或跨域

原因：后端未启动、端口不一致，或没有经过 Vite 代理。

处理：

- 确认 <http://localhost:8080/api/public/room-types> 可访问；
- 确认 `vite.config.js` 的代理目标与后端端口一致；
- 生产环境由 Nginx 把 `/api` 转发到后端，不要在前端写死后端域名。

### 7.9 中文乱码

原因：数据库或连接字符集不是 `utf8mb4`。

处理：

```sql
ALTER DATABASE homestay CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

连接串需包含 `useUnicode=true&characterEncoding=utf8`。

### 7.10 日期少一天或多一天

原因：把离店日也当成了占用夜。

处理：记住规则是 `[入住日, 离店日)`。11-20 入住、11-22 离店是两晚，只占 11-20 和 11-21。

### 8.4 配置 Nginx

```nginx
server {
    listen 80;
    server_name example.com;

    root /var/www/homestay;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

把 `homestay-web/dist/` 的内容复制到 `/var/www/homestay`。`try_files` 保证刷新前端路由时不会 404。

## 9. 二次开发指引

### 9.1 新增一个后端接口

以“房型评价”为例：

1. 在 `homestay-booking/src/main/java/com/homestay/` 下新建模块包；
2. 按 `entity → mapper → dto → service → controller` 的顺序添加文件；
3. Controller 返回 `ApiResponse.ok(data)`，异常抛 `BizException`；
4. 管理端接口放在 `/api/admin/**` 下，自动受房东权限保护；
5. 公开查询放在 `/api/public/**` 下；
6. 涉及多表写入时在 Service 方法上加 `@Transactional`；
7. 新增表时把建表语句追加到 `db/schema.sql`，使用 `CREATE TABLE IF NOT EXISTS`。

### 9.2 新增一个前端页面

1. 在 `src/views/` 或 `src/views/admin/` 新建 `.vue` 文件；
2. 在 `src/api/index.js` 中增加接口函数，不要在页面里直接写 axios；
3. 在 `src/router/index.js` 注册路由，管理端页面放在 `/admin` 子路由下；
4. 管理端页面加 `meta: { requiresHost: true }`；
5. 表格页复用现有模式：筛选条件、分页、弹窗表单、删除确认、操作后 `load()`。

### 9.3 修改库存或订单逻辑时的注意事项

- 库存扣减必须使用带 `stock >= n` 条件的 UPDATE，并检查影响行数；
- 扣库存、写订单、分配房间必须在同一事务内；
- 新增会改变可售量的操作时，同步检查搜索、报价、下单三处逻辑；
- 修改状态流转时同步更新 `OrderStatus` 和前端的按钮显示条件；
- 取消、拒绝必须按 `order_stay` 逐晚归还，不能只按天数估算；
- 不要为了接单去改动已有订单的房号。

## 10. 数据备份与恢复

### 10.1 备份

```bash
mysqldump -u homestay_app -p \
  --single-transaction \
  --default-character-set=utf8mb4 \
  homestay > homestay_$(date +%Y%m%d).sql
```

Windows PowerShell：

```powershell
mysqldump -u homestay_app -p --single-transaction --default-character-set=utf8mb4 homestay > homestay_backup.sql
```

### 10.2 恢复

```bash
mysql -u homestay_app -p --default-character-set=utf8mb4 homestay < homestay_backup.sql
```

恢复前请停止后端，避免写入冲突。恢复后再启动后端，`schema.sql` 只会补建缺失的表，不会清空数据。

### 10.3 备份建议

- 订单和日历数据每天至少备份一次；
- 备份文件不要放在 Web 可访问目录；
- 定期在测试库验证备份可恢复，而不是只确认文件存在。
