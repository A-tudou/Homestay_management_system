## 1. 全链路总览

一次用户操作的完整链路：

```
前端页面 (.vue)
   │  调用  api/index.js 里的方法（声明路径和参数）
   ▼
api/index.js ──► http.js（axios 实例，baseURL=/api）
   │  请求拦截器：加 Authorization: Bearer {token}
   │  响应拦截器：解包 { code, message, data }，code≠0 报错
   ▼
后端 Controller（@RequestMapping 匹配路径）
   │  参数校验（@Valid）、取当前登录用户（Authentication）
   ▼
Service（@Service，业务逻辑，@Transactional 事务）
   │  调用 Mapper 读写数据库
   ▼
Mapper（MyBatis-Plus BaseMapper + 自定义 SQL）
   │
   ▼
MySQL 表
```

反向数据流：数据库 → Mapper → Service → Controller → `ApiResponse{code,message,data}` → http.js 解包 → 页面拿到 `data`。

## 2. 全局基础设施（贯穿所有页面）

这一层不是某个页面，但每个页面的请求都经过它。

### 2.1 前端 HTTP 封装 `src/api/http.js`

[http.js](file:///C:/Users/z2138/Desktop/民宿管理系统/homestay-web/src/api/http.js) 做了三件事：

1. **`baseURL: '/api'`**：所有请求自动加 `/api` 前缀，开发时由 Vite 代理转发到后端 8080（见 `vite.config.js`）；
2. **请求拦截器**：每次请求实时从 `auth.token` 读 token，加到 `Authorization: Bearer ...` 头；
3. **响应拦截器**：后端统一返回 `{ code, message, data }`，`code === 0` 时直接返回 `data`（页面只处理业务数据）；非 0 时 `ElMessage.error` 并 reject。**401 时自动清空登录态并跳登录页**，记录原地址以便登录后返回。

```js
// 关键：401 统一处理，页面无需各自判断登录失效
if (status === 401) {
  auth.clear()
  const { default: router } = await import('../router')
  router.push({ path: '/login', query: { redirect: current.fullPath } })
}
```

### 2.2 登录态管理 `src/composables/useAuth.js`

[useAuth.js](file:///C:/Users/z2138/Desktop/民宿管理系统/homestay-web/src/composables/useAuth.js) 把 token 和用户信息持久化到 `localStorage`：

- `homestay_token`：JWT 令牌；
- `homestay_user`：当前用户信息（含 `role`）。

`setSession(token, user)` 登录时写入，`clear()` 退出时清除，`isAuthenticated()` 判断是否登录。刷新页面后从 `localStorage` 恢复，会话不丢失。

### 2.3 前端路由守卫 `src/router/index.js`

[router/index.js](file:///C:/Users/z2138/Desktop/民宿管理系统/homestay-web/src/router/index.js) 的 `beforeEach` 守卫：

- `meta.requiresAuth`：未登录跳 `/login`（如 `/orders`）；
- `meta.requiresHost`：进入管理端前校验 `role === 'HOST'`，非房东拦截回首页；若本地有 token 但缺 role，会先调 `/auth/me` 补齐；
- 已登录访问 `/login` 自动跳首页。

### 2.4 后端安全 `SecurityConfig`

[SecurityConfig.java](file:///C:/Users/z2138/Desktop/民宿管理系统/homestay-booking/src/main/java/com/homestay/config/SecurityConfig.java) 定义 URL 权限：

| 路径模式 | 权限 |
| --- | --- |
| `/api/auth/register`、`/api/auth/login`、`/api/public/**`、`/swagger-ui/**`、`/v3/api-docs/**` | 放行（无需登录） |
| `/api/admin/**` | 需 `HOST` 角色 |
| 其余（如 `/api/orders/**`） | 需登录 |

`JwtAuthenticationFilter` 在请求到达 Controller 前解析 token，构建 `LoginUser` 放进 `SecurityContext`；无效或过期直接返回 401。

## 6. 鉴权与权限对应

| 页面/接口 | 前端守卫 | 后端权限 | 取用户方式 |
| --- | --- | --- | --- |
| 房源列表、搜索、房型详情（公开部分） | 无 | `permitAll` | 不需要 |
| 登录、注册 | 已登录则跳首页 | `permitAll` | 不需要 |
| 我的订单 `/orders` | `requiresAuth` | 需登录 | `Authentication` 取 `userId`，只能看/改自己的 |
| 下单 `POST /orders` | 触发时若未登录跳登录 | 需登录 | 同上，订单 `user_id` 取自登录态 |
| 所有 `/admin/**` 页面和接口 | `requiresHost`（前端校验 role） | 需 `HOST` 角色（`SecurityConfig`） | `Authentication` 取操作人 id 写 `order_log.operator_id` |

**双重校验**：前端路由守卫负责页面级拦截（提升体验，避免进了页面才发现没权限），后端 `SecurityConfig` + `JwtAuthenticationFilter` 负责接口级兜底（安全底线，绕过前端直接调接口也会被拦）。
