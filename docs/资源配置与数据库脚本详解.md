## 1. 目录结构

```
src/main/resources/
├── application.yml          # 默认（开发）环境配置
├── application-prod.yml     # 生产环境配置（profile = prod 时激活）
└── db/
    └── schema.sql           # 建表脚本，启动时自动执行
```

共 3 个文件。resources 目录**没有** `static/` 或 `templates/`——因为这是前后端分离项目，前端静态资源由独立的 `homestay-web` 项目承载，后端只提供 API，不需要服务端渲染或静态托管。

## 2. 开发环境配置 application.yml

文件：`src/main/resources/application.yml`

这是默认激活的配置，不指定 profile 时使用。逐段讲解：

### 2.1 服务端口

```yaml
server:
  port: 8080
```

后端监听 8080。前端 Vite 开发服务器的代理目标也指向 8080（见前端 `vite.config.js`）。

### 2.2 数据源

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/homestay?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: homestay_app
    password: "Homestay@2026"
    driver-class-name: com.mysql.cj.jdbc.Driver
```

连接本地 MySQL 的 `homestay` 库，账号 `homestay_app`。JDBC URL 里的几个参数：

- `serverTimezone=Asia/Shanghai`：指定时区，避免 MySQL 8 默认时区导致日期偏移；
- `useSSL=false`：本地开发不强制 SSL；
- `allowPublicKeyRetrieval=true`：MySQL 8 默认的 `caching_sha2_password` 认证插件需要公钥，不开这个会连不上（仅适用于非 SSL 本地开发，生产应配合 SSL）；
- `characterEncoding=utf8`：保证中文写入不乱码。

> 开发环境的密码是明文写死的 `Homestay@2026`，方便本地一键启动。生产环境通过环境变量注入，见第 3 节。

### 2.3 SQL 初始化

```yaml
spring:
  sql:
    init:
      mode: always
      schema-locations: classpath:db/schema.sql
      encoding: UTF-8
```

`mode: always` 表示**每次启动都执行** `schema.sql`。这听起来危险，但脚本里全部是 `CREATE TABLE IF NOT EXISTS`，所以反复执行不会报错也不会删数据——已存在的表会被跳过。这让“拉代码 → 启动 → 自动建表”的本地体验非常顺滑，不需要手动初始化数据库。

### 2.4 Jackson 序列化

```yaml
spring:
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: Asia/Shanghai
```

全局 JSON 日期格式：`yyyy-MM-dd HH:mm:ss`，时区东八区。这样 `LocalDateTime` 字段序列化成前端能直接展示的字符串，而不是默认的数组格式 `[2026,1,1,12,0,0]`。

### 2.5 MyBatis-Plus

```yaml
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
  global-config:
    db-config:
      id-type: auto
```

- `map-underscore-to-camel-case: true`：数据库下划线列名自动映射到 Java 驼峰字段（如 `room_type_id` → `roomTypeId`），不需要在每个字段写 `@TableField`；
- `log-impl: StdOutImpl`：开发期把 SQL 打印到控制台，方便调试；注释里提示上线前改成 `NoLoggingImpl`；
- `id-type: auto`：全局主键策略为数据库自增，和实体上的 `@TableId(type = IdType.AUTO)` 一致。

### 2.6 Swagger / OpenAPI

```yaml
springdoc:
  swagger-ui:
    path: /swagger-ui.html
  api-docs:
    path: /v3/api-docs
```

启动后访问 `http://localhost:8080/swagger-ui.html` 可看到全部接口文档，由 `springdoc-openapi` 自动从 Controller 的 `@Tag` / `@Operation` 注解生成。

### 2.7 应用自定义配置（app）

```yaml
app:
  jwt:
    secret: homestay-booking-dev-secret-key-change-me-in-production-2026
    expire-minutes: 1440
  seed:
    enabled: false
```

`app.*` 是项目自定义的配置前缀，不是 Spring 标准项：

- `jwt.secret`：JWT 签名密钥。HS256 算法要求密钥至少 32 字节，这里写了一串长字符串满足要求；注释明确提示“生产环境务必替换”；
- `jwt.expire-minutes: 1440`：token 有效期 1440 分钟 = 24 小时；
- `seed.enabled: false`：演示数据开关。`true` 时 `DemoDataSeeder` 会在房型表为空时写入演示房型、房间、日历和账号，本地体验时可临时打开。

### 2.8 日志

```yaml
logging:
  level:
    com.homestay: debug
```

`com.homestay` 包下日志级别设为 `debug`，开发期能看到详细的 SQL 和业务日志。

## 3. 生产环境配置 application-prod.yml

文件：`src/main/resources/application-prod.yml`

这个配置**只在 `--spring.profiles.active=prod` 时激活**，覆盖开发配置里的同名项。顶部注释给出了启动方式：

```
java -jar homestay-booking-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

和开发配置的关键差异：

### 3.1 敏感项全部走环境变量

```yaml
server:
  port: ${SERVER_PORT:8080}

spring:
  datasource:
    url: ${DB_URL:jdbc:mysql://localhost:3306/homestay?...}
    username: ${DB_USERNAME:homestay_app}
    password: ${DB_PASSWORD}          # 无默认值，必须注入
```

`${VAR:default}` 是 Spring 的占位符语法：优先取环境变量 `VAR`，没有则用 `default`。生产配置的设计原则：

- **必须注入的项不给默认值**：`DB_PASSWORD`、`JWT_SECRET` 没有默认值，环境变量缺失时启动直接失败，**避免误用开发默认值**；
- **可回退的项给默认值**：`SERVER_PORT` 默认 8080、`DB_USERNAME` 默认 `homestay_app`，部署时通常不需要改；
- `JWT_SECRET` 必须注入且不少于 32 字节，否则签名验证失败。

### 3.2 关闭 SQL 日志

```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.nologging.NoLoggingImpl
```

生产环境不打印 SQL，避免日志膨胀和潜在的敏感信息（SQL 里可能带参数值）泄漏。

### 3.3 关闭演示数据

```yaml
app:
  seed:
    enabled: false
```

生产环境固定关闭 seeder，避免误写演示数据。

### 3.4 日志级别与文件输出

```yaml
logging:
  level:
    com.homestay: info
  file:
    name: ${LOG_FILE:logs/homestay-booking.log}
```

- 日志级别降到 `info`，减少生产日志量；
- 同时输出到文件 `logs/homestay-booking.log`（可用 `LOG_FILE` 环境变量改路径），方便持久化和采集。

### 3.5 开发配置的项自动继承

`application-prod.yml` 没有重复写 `jackson`、`springdoc`、`app.jwt.expire-minutes` 等配置，这些会从 `application.yml` **继承**。Spring Boot 的多 profile 机制是合并而非替换：激活 prod 时，先加载 `application.yml` 再加载 `application-prod.yml`，后者覆盖前者的同名项。所以生产环境同样会：

- 启动时执行 `schema.sql` 建表（`mode: always` 继承自开发配置）；
- Jackson 日期格式保持 `yyyy-MM-dd HH:mm:ss`；
- token 有效期默认 1440 分钟。

## 4. 数据库建表脚本 schema.sql

文件：`src/main/resources/db/schema.sql`

共 8 张表，全部用 `CREATE TABLE IF NOT EXISTS`，可反复执行。按业务域分组：

### 4.1 用户域（1 张）

**`users`** —— 房客与房东共用，靠 `role` 区分。唯一键 `uk_users_username`。

### 4.2 房源域（3 张）

- **`room_type`** —— 房型（售卖单位），含基准价、人数、床型、面积、封面图、上架状态。索引 `idx_room_type_status` 加速按上架状态筛选；
- **`room`** —— 物理房间，属于某房型，含房号、楼层、维修状态。唯一键 `uk_room_no`（房号全局唯一）、索引 `idx_room_type`（按房型查房间）；
- **`room_calendar`** —— 日历价格与库存（核心表），房型 × 日期唯一。含价格、库存、开放状态、**乐观锁版本号 `version`**。唯一键 `uk_type_date (room_type_id, stay_date)`、索引 `idx_stay_date`。

### 4.3 交易域（4 张）

- **`orders`** —— 订单主表，含订单号、日期区间、晚数、间数、总额、状态、联系人。唯一键 `uk_order_no`，索引 `idx_user`、`idx_room_type_date`、`idx_status`；
- **`order_room`** —— 订单分到的物理房间，一单多间有多行。唯一键 `uk_order_room (order_id, room_id)`；
- **`order_stay`** —— 订单占用的每一晚，用于取消时逐晚归还库存。唯一键 `uk_order_date (order_id, stay_date)`；
- **`order_log`** —— 订单状态流转日志，含变更前/后状态、操作人。索引 `idx_order`。

### 4.2 设计特点

- **全部 `IF NOT EXISTS`**：配合 `spring.sql.init.mode=always`，每次启动都安全执行；
- **无外键约束**：表之间没有 `FOREIGN KEY`，引用完整性由 Service 层校验。这是课程项目的取舍——建表灵活、灌数据方便，但生产建议补外键或定时对账；
- **时间字段由 DB 维护**：`created_at DEFAULT CURRENT_TIMESTAMP`、`updated_at DEFAULT ... ON UPDATE CURRENT_TIMESTAMP`，应用层不需要手动管理时间；
- **字符集统一 `utf8mb4`**：支持完整 Unicode（含 emoji），避免中文乱码；
- **引擎统一 InnoDB**：支持事务和行锁，这是订单并发扣库存能正确工作的基础（MyISAM 不支持事务）。

> 8 张表的详细字段说明分别见各模块文档：[用户模块](用户模块代码详解.md)、[房间模块](房间模块代码详解.md)、[订单模块](订单模块代码详解.md)。

## 5. 多环境配置切换机制

Spring Boot 的 profile 机制：

```
启动时不指定 profile
  → 只加载 application.yml（开发配置）

启动时加 --spring.profiles.active=prod
  → 先加载 application.yml，再加载 application-prod.yml
  → prod 里的同名项覆盖 yml 里的值
```

实际效果：

| 配置项 | 开发环境 | 生产环境 |
| --- | --- | --- |
| 服务端口 | 8080 | `${SERVER_PORT:8080}` |
| 数据库密码 | 明文 `Homestay@2026` | 必须注入 `DB_PASSWORD` |
| JWT 密钥 | 写死的开发密钥 | 必须注入 `JWT_SECRET` |
| SQL 日志 | 打印到控制台 | 关闭 |
| 业务日志级别 | debug | info |
| 日志文件 | 不输出 | `logs/homestay-booking.log` |
| 演示数据 | `false`（可手动改 true） | `false` |
| 建表脚本 | 每次启动执行 | 每次启动执行（继承） |

切换命令：

```bash
# 开发
java -jar homestay-booking.jar

# 生产
java -jar homestay-booking.jar --spring.profiles.active=prod \
  -D DB_PASSWORD=xxx -D JWT_SECRET=xxx
```

## 7. 关键设计点

### 7.1 建表脚本随启动自动执行

`spring.sql.init.mode=always` + 全部 `IF NOT EXISTS`，让项目“拉下来就能跑”，不需要提前手动建表。这对课程演示和新人上手非常友好。代价是生产环境每次启动都会跑一遍 SQL（虽然 IF NOT EXISTS 很快），如果未来表结构变更需要数据迁移，这套机制就不够了，得引入 Flyway 等迁移工具。

### 7.2 开发便利与生产安全分离

- 开发配置把密码、密钥写死，方便本地启动；
- 生产配置把敏感项改成**无默认值的环境变量**，缺失就启动失败。

这种“开发随便跑、生产必须配”的设计，既保证了开发效率，又防止了“把开发默认密钥带上生产”的常见事故。

### 7.3 profile 合并而非替换

`application-prod.yml` 只写差异项，其余从 `application.yml` 继承。这减少了配置重复，也避免了“改了开发配置忘了同步生产”的不一致。但要注意：如果某个配置项**只在生产需要、开发不需要**（如 `logging.file.name`），就只能写在 prod 文件里；如果**只在开发需要**（如 SQL 日志），在 prod 里覆盖掉。

### 7.4 JWT 密钥长度约束

`application.yml` 注释明确写了“HS256 要求密钥至少 32 字节”。`JwtTokenProvider` 用的是 `HMAC-SHA256` 算法，密钥太短会在启动时报 `WeakKeyException`。当前开发密钥是一串 50+ 字符的字符串，满足要求；生产注入的 `JWT_SECRET` 也必须满足。

### 7.5 演示数据开关防误写

`app.seed.enabled` 默认 `false`，即使配置成 `true`，`DemoDataSeeder` 也只在房型表为空时写入（幂等），不会重复灌数据。这是双保险：配置开关 + 数据判空。

## 8. 边界与可改进点

1. **无数据库版本迁移工具**：`schema.sql` 只能建表，不能做“加字段、改类型”这类增量迁移。表结构变更时需要手动改库。生产化建议引入 Flyway 或 Liquibase，把每个版本的变更脚本纳入版本控制。

2. **开发配置明文密码提交到仓库**：`Homestay@2026` 是写死在 `application.yml` 里并提交到 Git 的。虽然注释提示生产要替换，但仓库里仍有明文。建议开发配置也改成环境变量，或用 `application-local.yml`（gitignore）放本地敏感配置。

3. **JWT 密钥也提交到仓库**：开发密钥 `homestay-booking-dev-secret-key-change-me-in-production-2026` 在 `application.yml` 里。如果有人误把开发配置用于生产，这个公开的密钥会让 JWT 可被伪造。应确保生产强制注入独立密钥。

4. **`spring.sql.init.mode=always` 在生产有风险**：每次启动执行 schema.sql，虽然 IF NOT EXISTS 安全，但如果脚本未来加入了非幂等语句（如 ALTER），可能在生产误执行。建议生产改成 `mode: never`，由迁移工具管理表结构。

5. **日志文件无滚动策略**：生产配置只指定了日志文件名，没有配置滚动大小和保留天数。长时间运行会导致单个日志文件过大。可加 `logging.logback.rollingpolicy` 配置。

6. **无连接池配置**：`spring.datasource` 没有显式配置 HikariCP 的最大连接数、超时等，用的是 Spring Boot 默认值（最大 10 连接）。高并发下可能不够，需要根据负载调优。

7. **`allowPublicKeyRetrieval=true` 仅限非 SSL**：JDBC URL 里这个参数是为了本地开发连 MySQL 8。生产环境如果用 SSL 连接，应移除该参数并配置 SSL 证书。
